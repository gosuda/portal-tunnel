# Implementation Invariants

This file records constraints the implementation must keep whose reason lies outside the code: protocol rules, security reasoning, platform behavior, or ordering with an external cause. Entries group by package; where [architecture.md](architecture.md) or [relay-behavior.md](relay-behavior.md) already states a rule, the entry points to that section instead of repeating it.

## portal

- `leaseRecord.pinnedChain` (portal/record.go): Keep only the public PEM chain served when the lease registered. Never store a key. Treat nil as unknown and never ask such a lease to re-register.
- `leaseRecord.revokeBridgesLocked` (portal/record.go): MUST keep revoked workers counted until they finish. Re-allowing an identity admits only new reservations and never revives a canceled bridge. Deadlines interrupt current I/O, but a later framing write can replace the write deadline with the helper five second limit. Close endpoints outside these locks. Never copy application data with the canceled context.
- `Server.syncLeaseDNS` (portal/record.go): Queue DNS sync while the lease is still the current live record. A concurrent unregister or expiry must either happen after this enqueue or make this stale sync a no-op.
- `leaseRegistry.accessRevision` (portal/lease.go): Access revisions describe complete relay snapshots, so the newest observed revision fences older publications for every identity. Keep this watermark when idle blocked entries expire to prevent stale replay.
- `leaseRegistry.setIdentityAccess` (portal/lease.go): A TLS close can wait on its peer, so it MUST NOT hold the registry lock.
- `leaseRegistry.applyIdentityAccessLocked` (portal/lease.go): DetachOwner only changes cache metadata. Keep revocation ordered with access publication so an older deny cannot detach newer content.
- `leaseRecord.lastSelected` (portal/record.go): Holds the registry-serialized replica selection order. Compare it only between leases of one identity, so unrelated traffic cannot skew round-robin order.
- `leaseRegistry.activateBridge` (portal/lease.go): Repeat admission and take ownership of the reverse stream before framing. A non-nil inbound connection passes to the bridge only after framing. Lease closure interrupts framing by closing the reverse stream. A routing deny cancels the reservation; the framing helper can still use its own five-second write limit before the worker exits, and the canceled context prevents copying application data afterward. A retrying caller has already closed the previous failed framing stream.
- `leaseRegistry.recordForVerifiedLeaseLocked` (portal/lease.go): Tell a missing lease from a stale credential. The caller has already verified the credential and holds `r.mu`.
- `leaseRegistry.admitBridge` (portal/lease.go): Count pending acquisition and active traffic together. Keep mutable lease facts under the registry lock. Lock order is registry then record.
- `leaseRegistry.stalePinLocked` (portal/lease.go): Report stale only from the chain the lease registered under, the one the SDK pinned. The caller holds `r.mu`. A tenant pins its chain just after registering, so a renewal in between can make the record older than the pin; that costs at most one needless re-registration and needs no other source for the chain. A chain that verifies is remembered, so the check runs once per lease and change. A tenant that cannot reach `/v1/sign`, because the relay holds no key for the chain it presents or the relay API certificate no longer verifies against the pinned chain, fails every handshake until it registers again, which `lease_not_found` makes it do; the new record then pins the current chain, so each change asks each lease at most once. Never verify against a chain that itself only verified, such as one that carries a cross-signed root, since that would accept what the pin does not.
- `leaseRegistry.closeRecord` (portal/lease.go): Release sockets before making their ports available for reuse. Resource shutdown MUST NOT hold the registry lock. The reservation owner check makes repeated cleanup harmless even after a port has been reassigned.
- `unapprovedLeaseRetryAfter` (portal/api_server.go): Space out retries that cost pre-auth budget, which the same source approved registrations also need. Each waiting client spends a unit per retry and the default budget refills 10 a minute, so this keeps dozens of waiting clients from draining it. The value is `"300"`.
- `Server.apiHandler` (portal/api_server.go): A nil `*http.ServeMux` reaches this handler as a typed-nil interface: it compares non-nil, then panics on the first ServeHTTP call. Normalize it so the root fallback below still covers `Start(ctx, nil)`.
- `Server.apiHandler` IP-literal (portal/api_server.go): An IP-literal Host carries no tenant identity, since cache entries are keyed by hostname, so it stays on the control plane.
- `Server.HandleRelayDiscoveryAnnounce` (portal/api_server.go): The relay own URL is established locally, not through announces. `RelaySet.InsertCandidate` owns the public destination policy for all untrusted descriptors, including gossiped ones.
- `Server.HandleConnect` (portal/api_server.go): The WebSocket carrier has its own credential grammar, and overlay routing only speaks the raw carrier, so tell them apart before reading either.
- `Server.HandleStaticCache` (portal/api_server.go): Capture the cache generation before the access check: revocation either rejects admission here or invalidates this generation before cache publication.
- `Server.serveCachedSite` TLS opt-in (portal/api_server.go): Tenant hosts never reach the relay control plane, including on a connection with a mismatched Host header. TLS termination here is explicit cache opt-in.
- `Server.serveCachedSite` DialTLSContext (portal/api_server.go): The relay is the TLS client on this fallback: no routed client hello exists at issue time, so the binding starts pending and is pinned to the relay own ClientHello on first write.
- `Server.serveCachedSite` trust (portal/api_server.go): The tenant presents the relay chain it pinned, which can be one a renewal replaced; trust what the relay still signs for.
- `Server.Serve` redirect (portal/server.go): Canonical portal only: never forward request hosts, paths, or queries.
- `Server.start` worker pool (portal/server.go): A status-byte write may wait for the reverse connection deadline. A fixed pool prevents one slow peer from blocking all lease admissions without creating unbounded admission goroutines.
- `Server.admitReverseOffer` (portal/server.go): Compose overlay admission with the lease stream while a reserved stream slot keeps the accepted status and queued session atomic.
- `Server.Shutdown` (portal/server.go): Shutdown can precede the Serve goroutine registering its listener.
- `Server.promoteIngress` (portal/server.go): Transfer an inspected tenant socket to the bridge budget. Root and control-plane handoff never uses this budget, even at tenant capacity.
- `Server.runPublicIngress` SNI quirk (portal/server.go): Go omits the SNI extension for IP-literal hosts and tenant hostnames are always DNS names, so a connection without a server name targets the canonical root origin; route it there instead of failing the handshake for IP-literal `PORTAL_URL` deployments.
- `Server.handleQUICBackhaulConn` codes (portal/server.go): The SDK QUIC loop reads no code here, so a denial needs none of its own.
- `Server.handleQUICBackhaulConn` deadline (portal/server.go): The response is part of authentication. Keep its deadline through the write, then settle cancellation before publishing success.

## portal/acme

- `Manager.pendingDNSAddress` (portal/acme/acme.go): Guard this flag with `commandMu` and clear it only after address-record synchronization.
- `(Manager).manualCertificateOverride` (portal/acme/acme.go): The account key is created before any registration, so it marks ACME state for every CA directory, whatever name that directory registration has. Existing ACME state distinguishes a cached managed certificate from an operator-supplied certificate.
- `(Manager).provision` (portal/acme/acme.go): Every issuance carries a new private key, so what the relay serves must change together with the files. Refuse a pair that does not parse before writing anything, so the files and what is served cannot disagree.
- Const block (portal/acme/certificate.go): `localDevelopmentCertificateValidity` is the longest validity Apple platforms accept for a TLS server certificate, even from a root the user trusts. Safari refuses a longer one however it is trusted. `maxRenewExpiryFloor` bounds how long ARI may defer renewal: renew a certificate with less lifetime left whatever the CA suggests. `minARIRecheckDelay` keeps a CA Retry-After from driving the renewal check faster than hourly.
- `reusableCertificate`, `registrationFilePath`, `certificateFilePaths` (portal/acme/certificate.go): Each directory keeps its own certificate. An account exists only at the CA that created it, and lego signs requests with the stored account URL. Only a certificate that the configured CA issued may be served or renewed. Production keeps legacy names.
- `certificateUsable` (portal/acme/certificate.go): MUST NOT check NotBefore. A certificate that is not valid yet on this clock was issued moments ago, and ordering another would not help but would count against the CA duplicate-certificate rate limit on every start.
- `NormalizeCADirURL` (portal/acme/certificate.go): The scheme and host are case-insensitive, and the files of a CA are named after this string, so two spellings of one directory MUST NOT look like two CAs.
- `Manager.syncDNS` addresses (portal/acme/provider.go): MUST return discovered addresses even if base-record updates fail, so tracked-record maintenance can reuse them without repeating discovery. Manual certificates bypass external address-record management, but the embedded authoritative zone still needs its address before it can serve the relay.
- `Manager.syncDNS` addressless zone (portal/acme/provider.go): The embedded zone can serve without address records. Keep the usable certificate and let the existing short retry ticker initialize it.
- `servedMaterial` (portal/acme/material.go): This is the certificate the relay serves now, and the earlier ones that tenants may still present: a tenant pins the chain the relay served when its lease client was created and keeps presenting it to visitors after a renewal replaced it.
- `serve` (portal/acme/material.go): This path is built for scheduled renewal, where the replaced certificate is still valid and tenants still present it. It keeps the replaced key signing until that certificate expires even when the renewal was meant to retire it, as after a revocation or a key compromise. For a compromise, restart the relay: the retired material lives in memory only, and the restart also drops every lease, so tenants re-pin the chain on disk.
- `dnsRetryBackoffs`, `rearmRetryTimer`, `syncDNSAttempt` (portal/acme/maintenance.go): `dnsRetryBackoffs` schedules the early retries while the embedded zone is still waiting for its public address. Once the table is exhausted the regular interval applies again. A timer instead of a ticker lets the CA ARI Retry-After and the expiry floor set the next renewal check. A timer instead of a ticker lets the pending embedded DNS address follow the fast early retry schedule. `EnsureCertificate` has usually run before Start, so the zone can already be pending on its address right after a relay restart. `rearmRetryTimer` stops, drains, and resets the retry timer. The drain is required because resetting an already-fired timer would make it fire immediately on every subsequent loop iteration. `syncDNSAttempt` centralizes the bookkeeping shared by the regular ticker and the pending-address retry path. Embedded signing remains pending: it does not authenticate the parent chain and MUST NOT suppress DNSSEC synchronization.

### embedded

- `loadSigningKey` existing key (portal/acme/embedded/dnssec.go): A single file binds the private key to its zone and DNSKEY. Never regenerate an unreadable or malformed existing key: the parent DS may already trust it.
- `loadSigningKey` key tag (portal/acme/embedded/dnssec.go): `miekg/dns` treats key tag zero as an unset signing parameter. Never persist that otherwise-valid key, which this signer cannot use.
- `loadSigningKey` key match (portal/acme/embedded/dnssec.go): The BIND parser does not check that the public and private keys match.
- `signedZone` snapshot (portal/acme/embedded/dnssec.go): This is the one immutable authoritative snapshot. Mutations invalidate it by serial; refresh is lazy, before answering, so idle zones never serve expired signatures. Failed signing returns SERVFAIL, never unsigned data.
- `signedZone` synthesis (portal/acme/embedded/dnssec.go): Include empty non-terminals. Materialize each address family and its wildcard at every closest encloser so explicit TXT records do not shadow zone-wide address synthesis (RFC 4592).
- `signedZone` wildcard (portal/acme/embedded/dnssec.go): An explicit wildcard already represents synthesis at its parent, not a separate closest encloser requiring another wildcard beneath it.
- `compareDNSNames` (portal/acme/embedded/dnssec.go): RFC 4034 section 6.1 orders labels from the root outward, by unsigned unescaped octets, with a shorter label sorting first. Wire packing also handles escaped labels in queries, not only hostname-style owner names.
- `Provider.started` (portal/acme/embedded/provider.go): This flag marks a provider created through New, the only caller allowed to arm the delegated-path self-check. Direct constructions such as unit tests MUST NOT launch external resolver lookups as a side effect.
- `verifyDelegatedPath` (portal/acme/embedded/provider.go): This performs the one-shot delegated-path self-check: it resolves a fresh random label through the system resolver and compares the answer with the synthesized address, proving the parent delegation actually reaches this server. It is log-only and never blocks the caller. It costs one recursive resolver round trip per address family and provider.
- `ServeDNS` (portal/acme/embedded/server.go): SERVFAIL is the only internal failure; client-caused codes (REFUSED, FORMERR, NOTIMP) stay at Debug. Port 53 is a public listener and every query can be flooded (issue #518 review).
- `answer` closest ancestor (portal/acme/embedded/server.go): Walk to the closest existing ancestor, not merely the apex: explicit records and empty non-terminals both block more distant wildcards.
- `answer` RRSIG (portal/acme/embedded/server.go): RRSIG is directly queryable even without DO (RFC 4035 section 3.1.1).
- `answer` pending names (portal/acme/embedded/server.go): The snapshot carries no synthesized addresses, so every missing name is a tenant name whose answer is still pending the public IP sync. REFUSED without an SOA keeps resolvers from negative-caching it for the whole sync window (issue #516); NXDOMAIN stays reserved for the genuinely-missing-name case once the zone is address-capable.
- `answer` denial proofs (portal/acme/embedded/server.go): Exact and wildcard NODATA proves the missing type at its actual owner. NXDOMAIN additionally proves that the closest-encloser wildcard is absent. Together with next-closer denial this covers deep names.

## portal/discovery

- `filterCandidatePool` (portal/discovery/relayset.go): A bootstrap URL configured by the operator stays eligible as a URL-only single-hop fallback until a direct probe verifies it, but a descriptor squatted on a bootstrap URL by an untrusted candidate is not eligible at all.
- `molsMultipliers` (portal/discovery/mols.go): Even orders admit no linear orthogonal pair, since all units mod an even order are odd, so m1 minus m2 is always even. Then ok is false and callers fall back to the single-square (1,1) score, which stays deterministic and duplicate-free per row without MOLS fairness.
- `molsDigest` (portal/discovery/mols.go): The selection key is the per-client secret that makes rankings unpredictable to outside observers and immune to relay URL grinding. The SDK derives it from the client persisted identity secret, and it stays stable across restarts.
- `molsCongestionMode` (portal/discovery/mols.go): Fallback relays are excluded: their multi-second RTTs reflect unhealthiness, not congestion, and would otherwise flip the ranking into congestion inversion spuriously.
- `rankRelayPool` (portal/discovery/mols.go): A nil key keeps the ranking deterministic for tooling and tests.
- `selectPriority` (portal/discovery/mols.go): Explicit URLs remain selectable if discovery evicts their candidate. Retained state still enforces bans, backoff, and transport requirements.
- `applyActiveStickiness` (portal/discovery/mols.go): The destination is the lowest-ranked swap target. The existing `TestMOLSPressureSwapsTopRelayOnly` covers it, so no new test was written.
- `requirePublicRelayURL` (portal/discovery/public_relay.go): This checks the static part of the discovery trust boundary. Names MUST also pass the resolved-address check on every new connection.
- `dialPublicRelay` (portal/discovery/public_relay.go): Dial the IP, rather than the hostname, to prevent a second DNS lookup from rebinding to an internal address. net/http retains the original hostname for TLS certificate verification and the HTTP Host header.
- `dialPublicRelay` transport (portal/discovery/public_relay.go): HTTP transports can keep a dial alive after its request times out. Bound DNS resolution and all connection attempts independently.
- Refresher client construction (portal/discovery/refresher.go): Untrusted descriptors MUST never use a proxy that can resolve or dial their hostname on our behalf. Resolve and pin only public IPs directly.
- `refreshOneHTTPS` local trust (portal/discovery/refresher.go): Local TLS trust is only permitted for explicitly configured peers.
- `refreshOneHTTPS` incompatibility (portal/discovery/refresher.go): See [relay-behavior.md](relay-behavior.md), Responses and Executable evidence. Protocol incompatibility is visibility metadata there, not a health failure.
- `RelaySet` (portal/discovery/relayset.go): Evicting the last URL slot for an identity, via LRU or explicit removal, MUST NOT forget the rollback anchor, or a captured older-but-unexpired descriptor could replay after eviction. Tombstones expire once now passes IssuedAt plus AnnounceMaxValidity, after which replayable descriptors are themselves expired. Both maps sit under `s.mu`; `*Locked` methods assume the caller holds the write lock, which prevents nested-locking deadlocks, notably `ApplyRelayDiscoveryResponse` holding the write lock for the batch.
- `banFromPoolLocked` (portal/discovery/relayset.go): A local ban outranks protocol-mismatch visibility and drops the observed release: both return only after a fresh direct contact.
- `mergeLocalRelayState` (portal/discovery/relayset.go): Trust never transfers across an identity change on the same URL: a takeover after descriptor expiry must start over as a candidate. A genuine rotation re-verifies through the authoritative probe path.
- `upsertDescriptorLocked` (portal/discovery/relayset.go): `allowCrossIdentityTakeover` MUST be true only when the caller has directly contacted the URL and verified the response is signed by the announced identity, that is, an authoritative refresh. Gossip propagation and the announce endpoint MUST pass false. Equal IssuedAt values at the same URL and signing identity MUST carry the same canonical signed contents; idempotent re-broadcasts may refresh local telemetry, but conflicting statements cannot replace the retained observation.
- Untrusted-ingestion invariant (portal/discovery/relayset.go): Whichever path admitted the descriptor, announce, hop route, or gossiped discovery response, a single signing identity never holds more unverified entries than the per-identity cap. Verified entries are never evicted by this cap.
- `discoveryRelayStateLocked` (portal/discovery/relayset.go): Only a direct response from an explicitly configured bootstrap relay may advertise its own local or private URL.
- `ApplyRelayDiscoveryResponse` contradiction (portal/discovery/relayset.go): See [relay-behavior.md](relay-behavior.md), Responses. A signed contradiction is not a successful recovery probe there, and gossip cannot use it to mutate health or sanction the signer.
- `ApplyRelayDiscoveryResponse` IssuedAt (portal/discovery/relayset.go): The monotonic-IssuedAt check rejected this descriptor as a rollback, or ignored it because a newer same-identity descriptor for this URL is already present. The cryptographic identity in `s.relays` is unchanged, but if the authoritative target was reached, still credit it as alive on its existing URL slot.
- `ApplyRelayDiscoveryResponse` mismatch (portal/discovery/relayset.go): Protocol mismatch outranks a missing target descriptor: the response arrived over HTTPS and its protocol version is the observation this package records, so the refresher MUST classify it as `ErrProtocolMismatch` rather than a health failure even when the older relay omits its own descriptor from the response.
- `recordReleaseObservationLocked` (portal/discovery/relayset.go): The authoritative refresher poll is the only writer. Gossip and announce batches carry no release of their own and MUST NOT mint or refresh observations. Record regardless of protocol match (issue #512): the protocol label is only a fallback when no release is known. An empty value, from an older build that stopped reporting, drops the observation: latest direct observation wins.
- `enforceIdentityCapLocked` (portal/discovery/relayset.go): Overflow evicts that identity own oldest candidates by LastSeenAt, so a flooding identity recycles its own slots instead of displacing other relays through the global cap. The keyIndex rollback anchors survive eviction by design.
- `enforceCapLocked` (portal/discovery/relayset.go): An operator misconfig that lists more than MaxAnnouncedRelays bootstraps is surfaced by the resulting overflow rather than silently violating operator intent.
- `relayTrust` (portal/discovery/relaystate.go): Verifying a relay never verifies the other relays its discovery response mentions; admit those as candidates like any other untrusted descriptor.
- `relayCandidate` (portal/discovery/relaystate.go): Candidates remain refresh-poll targets, but they are excluded from Descriptors, automatic route selection, and this relay own gossip output until promoted.

## portal/identity

- `NewRegisterChallenge` (portal/identity/register_challenge.go): Host-derived fields are retained in the SIWE message and are not covered by the HTTP JSON body limit.
- `ValidateRegisterSIWEChallenge` (portal/identity/register_challenge.go): The Portal formatter has twelve lines. Extract only the two relay-selected values; regenerate all other fields from trusted client context.
- `ethereumPersonalMessageHash` (portal/identity/secp256k1.go): This is the shared EIP-191 personal-sign digest for both signing and recovery. The prefix counts UTF-8 bytes, not characters.
- `signEthereumPersonalMessage` (portal/identity/secp256k1.go): Ethereum signatures are r || s || v. Accept the personal_sign recovery values 27 and 28 and their normalized 0 and 1 forms, not transaction chain IDs.
- SIWE wallet authentication (portal/identity/siwe_auth.go): Challenges are stateless and tamper-evident: Issue encodes the challenge payload into an HMAC-signed token instead of storing pending state, so issuance consumes no server state and an unauthenticated flood of challenge requests cannot exhaust login capacity (issue #530). The token travels to the wallet as the opaque challenge ID; its embedded payload ID doubles as the SIWE request ID. Verification keeps no state either: a replayed token within its TTL re-authenticates the same wallet, which cannot create a new identity or bypass signature verification, so replay tracking, and the global capacity failure mode it would reintroduce, is deliberately omitted. By default each authenticator generates its challenge-signing key at construction, so recreating it invalidates outstanding challenges. Services can instead provide a shared key so outstanding challenges survive replica rotation. Source IP addresses and relay connection identities are deliberately not used to rate-limit issuance: neither is a trustworthy browser identity through relay transport, so limiting on them would only block the wrong clients.

- `staleLeaseError` (sdk/listener.go): Credentials this listener previously obtained are no longer valid on the relay: the in-memory lease registry was dropped by a relay restart, or the relay rotated its signing authority so the stored access token and reverse capability answer unauthorized before the missing-record check can answer lease-not-found. - `reverseTarget` (sdk/listener.go): Recheck on every reconnect, including after a failed gateway is replaced.

## sdk/appauth

- `applicationAuthStateTokenLimit` (sdk/appauth/appauth.go): Keep a signed login state cookie well under the roughly 4 KB a browser accepts, since the browser silently drops a larger one.
- `providerMinSessionTTL` (sdk/appauth/appauth.go): This is the shortest OIDC or SAML session, so a short-lived ID token or IdP session cannot produce a session that has already expired.
- `IssuedAtMillis` (sdk/appauth/appauth.go): This value is in milliseconds, because a tunnel that restarts within a second of a sign-in must still tell the session from its new hold.
- `oidcEmailVerified` (sdk/appauth/appauth.go): Decode the email_verified claim. OIDC defines a JSON boolean, but some providers send the string "true". Only true and "true" count as verified; any other value, or none, decodes as not verified instead of failing the whole claims decode, which would also lock out sub allowlists.
- `validateOIDCEndpoint` (sdk/appauth/appauth.go): Check an endpoint from the discovery document of issuerURL. Unlike an issuer identifier it may carry a query (RFC 6749 sections 3.1 and 3.2). The token endpoint receives the authorization code, PKCE verifier, and client secret, so an endpoint MUST be https unless the issuer itself is loopback http.
- `serveOIDCCallback` (sdk/appauth/appauth.go): `access_denied` is how a provider reports that the visitor declined, and also how some report an account without access to the client.
- `oauth2Config` (sdk/appauth/appauth.go): The auth style is named because the oauth2 default probes: it sends the one-time authorization code with the credentials in the Authorization header and, on any error, sends the same code again with them in the body.
- `client_secret_basic` in `oauth2Config` (sdk/appauth/appauth.go): This trailing style is the OIDC default.
- `exchangeAndVerify` (sdk/appauth/appauth.go): Load the keys before the exchange so an unreachable JWKS does not burn the one-time authorization code.
- `oidcVerificationKey` (sdk/appauth/appauth.go): Select what a token is verified against. go-jose finds a key in a set by the token kid and refuses a token without one, even when the set holds a single key. A provider that signs with one key may omit the kid, so use that key directly when it is a signing key.
- `minIdentityProofLength` (sdk/appauth/credential.go): Keep the proof long enough that a local process cannot guess it.
- `resolveApplicationAuthConfig` (sdk/appauth/credential.go): The proof is sent as a header value and is compared byte for byte by the upstream, so it is not trimmed here. The environment reader already trims the whitespace around `AUTH_IDENTITY_PROOF`. Accept only visible ASCII. Name both sources of the value, the flag and the environment variable, in errors, and never include the value itself.
- `resolveAllowlist` (sdk/appauth/credential.go): Read the allowlist of the provider from the key that may hold it. oidc and saml take both keys, because released configs hold the list under `--auth-allow`. email was never released with it, so it takes only the one.
- `applicationAuthClaims.HostEpoch` and `applicationAuth.hostEpoch` (sdk/appauth/appauth.go): The epoch is the relay alias ownership generation, independent of a lease or process lifetime. It supersedes the local `Since` fallback used with older relays; canonical hosts and older relays have no epoch. Replicas of one service share sessions and challenges within one epoch, and a new epoch ends them without waiting for clocks or token expiry.
- `oidcAuthenticator.serveLogin` and `samlAuthenticator.serveLogin` state cookie (sdk/appauth/appauth.go, sdk/appauth/saml.go): A login keeps its state in one cookie, so a request that never completes the login, such as a HEAD probe, MUST NOT overwrite the state of a login in progress.
- `serveEmailRequest` host (sdk/appauth/email.go): Take the host from the public list, never from the request: a link mailed for another host would send its token to whoever answers there.
- `emailRoutingCharacters` (sdk/appauth/email.go): These are ordinary address characters to net/mail, but a mail server can route on them: `user%evil.example@team.example` passes an `@team.example` entry, and such a server delivers it to `evil.example`.
- `binding` (sdk/appauth/email.go): Digest the SMTP server, the username, and the sender into every email session, so a change of the mail account ends the sessions of the links it mailed. Keep the password out: a session cookie MUST NOT carry anything to guess it from.
- `send` and `deliver` (sdk/appauth/email.go): The error comes from composing the mail, the SMTP server, or the connection, and never holds the password. `deliver` keeps the recipient out of it.
- `emailPlaintextHost` (sdk/appauth/email.go): Report whether an SMTP session to a host may stay plaintext: only for the names net/smtp itself sends a password to without TLS, so that a plaintext session can always sign in.
- `samlEntityIDLimit` (sdk/appauth/saml.go): This is the longest entity ID SAML allows (core 8.3.6).
- `binding` (sdk/appauth/saml.go): Digest the metadata source, the entity ID, and the subject attribute into every SAML session, since a subject only means something at the identity provider and in the form that produced it.
- `normalizeSAMLMetadataURL` (sdk/appauth/saml.go): Check where the identity provider metadata is fetched from. The metadata names the keys every assertion is verified against, so it MUST come over https unless it is on a loopback host. Unlike an OIDC issuer it may carry a query, as Entra ID federation metadata does.
- `parseSAMLMetadata` (sdk/appauth/saml.go): goxmldsig refuses a signature by a certificate outside its validity, so metadata whose certificates have all expired could never sign anyone in. Refuse it here so the startup check reports it.
- `serveLogin` (sdk/appauth/saml.go): Let a browser still signed in to the refused account straight back in unless the identity provider is asked to authenticate the visitor again.
- `setSAMLStateCookie` (sdk/appauth/saml.go): Set or, with maxAge -1, clear the login state. The identity provider posts the response from its own site, and a browser sends a SameSite=Lax cookie with no cross-site POST, so this one cookie is None.
- `serveSAMLACS` (sdk/appauth/saml.go): This is the assertion consumer service: the identity provider posts the response here. Only a response to a login this browser started counts, so a response the identity provider sends on its own, IdP-initiated SSO, finds no state and is refused.
- `serveSAMLACS` email (sdk/appauth/saml.go): SAML has no email_verified: the value the identity provider signed is the email it vouches for when it has the shape of one.
- `verify` (sdk/appauth/saml.go): Return the one assertion of a response to the login in state. gosaml2 checks the XML signature, a signed response, or else every assertion signed, never a mix, plus the issuer, the status, the bearer subject confirmation and its recipient and expiry, and a destination that is present. Check the rest here: the destination MUST be present, the response and its assertion MUST answer this login, the assertion MUST be restricted to this service provider and within its time conditions, and it MUST NOT have been used before.
- `verify` bearer check (sdk/appauth/saml.go): Gosaml2 refused an assertion without a bearer confirmation and its data.
- `checkSAMLConditions` (sdk/appauth/saml.go): A bearer assertion MUST name its audience (SAML profiles 4.1.4.2), and every restriction it carries MUST admit this service provider.
- `serveSAMLMetadata` (sdk/appauth/saml.go): Publish the service provider metadata for the host it is read at, for the identity provider to import: the entity ID and the ACS URL. Leave WantAssertionsSigned false, because `verify` accepts a signed response as well as signed assertions, never a response with neither, and offer no key, because this tunnel neither signs its requests nor accepts encrypted assertions.

- `runServer` domain report (cmd/relay-server/main.go): Always serve /sdk/domain by composing facilitator metadata onto server.DomainReport(), whether payments are enabled or not.
- `runServer` warn direction (cmd/relay-server/main.go): Any admin write on an auto relay saves that mode, and a saved mode wins. Warn only in this direction, because it leaves a private relay open.
- `runServer` embedder limits (cmd/relay-server/main.go): The default relay owns the Admin, x402 and frontend control routes. Embedders application fallback handlers retain their own body limits.
- `resolveX402Facilitator` (cmd/relay-server/main.go): An enabled facilitator without a payment recipient would advertise payments nothing can settle, so fail resolution instead of booting unusable. Normalize the recipient to a valid Sui address: it is published verbatim in the /sdk/domain facilitator metadata.
- `mountRelayRoutes` (cmd/relay-server/main.go): Portal payments settle only Sui USDC (docs/src/routes/self-hosting), so pin the facilitator allowlist to the network USDC asset; upstream default options would allowlist every gasless stablecoin.
- `domainResponse` (cmd/relay-server/main.go): Keep the x402 key on the wire (zero value marshals as {"enabled":false}) so disabled deployments keep today shape.

### policy

- `Mux` standalone shape (cmd/relay-server/policy/mux.go): No application handler: the relay answers its own root and 404s everything else, matching the standalone Serve(ctx, nil) shape.
- `Mux` revision retry (`publishAccess`) (cmd/relay-server/policy/mux.go): A newer committed snapshot may reach Portal while this request is paused. Retry a bounded number of times when Portal rejects the older revision; never apply stale values, and hold no relay lock across the Portal call.
- `Mux` redirect guard (final handler) (cmd/relay-server/policy/mux.go): ServeMux may redirect before invoking the fallback. Protect that short response here, preserving trailing slashes and escaped paths.
- `Mux` CORS (final handler) (cmd/relay-server/policy/mux.go): Answer CORS preflight here, before the fallback is called.
- `ControlBodyHandler` (cmd/relay-server/policy/control_body.go): net/http may drain the original body after the handler returns. Expire reads first, even when the handler rejected before decoding. Reverse carriers upgrade bodyless GET requests. Reject an HTTP body before hijacking so cleanup cannot expire a live reverse connection.
- `DefaultPreAuthConfig` (cmd/relay-server/policy/preauth.go): Allow 600 units/minute, which permits about 100 complete registrations/minute; keep the 200-unit burst, which permits about 33 simultaneous startups. Operators should tune this aggregate work budget to their relay capacity.
- `Store.Commit` (cmd/relay-server/policy/store.go): Revisions belong to this running relay; both Store and Portal start fresh on restart, so policy.json needs no revision field or schema migration.
- `ReputationStore` caps (cmd/relay-server/policy/reputation.go): Whole-file JSON is rewritten on each changed vote, so these caps keep the work per public POST small; identities persist for the life of the state file, so past the identity cap new identities are rejected.
- `persistedReputation` (cmd/relay-server/policy/reputation.go): A non-nil Comments also records that legacy comments.json has been imported, including an empty file.
- `resolveVoterLocked`, `ViewerHashFor` (cmd/relay-server/policy/reputation.go): A caller that drops every Set-Cookie header cannot create unlimited distinct voter identities. Without accounts, clients behind the same public IP share this identity.

## frontend

- `buildTunnelPreviewURL` (frontend/src/lib/tunnelCommand.ts): The short URL keeps the relay port (`relayAuthority` in `sdk/listener.go`); a browser leaves out the default 443.
- `mailAtom` and `visitorEmail` (frontend/src/lib/tunnelCommand.ts): `normalizeVisitorEmail` (`sdk/appauth/email.go`) takes a bare address that net/mail reads back unchanged, without the `%` and `!` that mail servers route on.
- `senderName` and `emailSender` (frontend/src/lib/tunnelCommand.ts): `parseSMTPFrom` (`sdk/appauth/email.go`) takes one address the way net/mail reads it: bare, or in angle brackets after a display name.
- `isOIDCIssuer` (frontend/src/lib/tunnelCommand.ts): `normalizeOIDCIssuerURL` also accepts http on a loopback host, which the builder does not offer.
- `isSAMLMetadataURL` (frontend/src/lib/tunnelCommand.ts): `normalizeSAMLMetadataURL` (`sdk/appauth/saml.go`) also accepts http on a loopback host, which the builder does not offer. Unlike an issuer, the metadata URL may carry a query.
- `isEmailSMTPAddr` (frontend/src/lib/tunnelCommand.ts): `validateSMTPAddr` (`sdk/appauth/email.go`) reads host:port the way net.SplitHostPort and strconv.Atoi do: an IPv6 host in brackets, a host without control characters, and a port from 1 to 65535.
- `validateTunnelAuth` (frontend/src/lib/tunnelCommand.ts): This reports what stops the generated command from being run as shown; empty when ready. It is the one owner of these rules: the copy gate and the notices next to each field both render from it.
- `buildAuthRedirectURLs` (frontend/src/lib/tunnelCommand.ts): These are the addresses, paths to register at an identity provider for the short URL on each relay in the command: the OIDC redirect address, or the SAML ACS or metadata address. They stay empty until the name is known. The gateway builds these from the host the visitor arrived on, so the address-bound URL Portal prints, and every relay discovery adds, need their own; those hosts are known only once Portal prints them.
- `applicationAuthHost` (frontend/src/lib/tunnelCommand.ts): This is the host a private link is bound to, read from the URL handed to the visitor the way `normalizeHost` (`sdk/appauth/credential.go`) reads it: an https URL or a bare host, without a path, query, or fragment. The URL parser also drops the `:443` Portal prints, as a browser leaves it out of the Host it sends. Empty when the address is unusable.
- `quotePowerShellValue` (frontend/src/lib/tunnelCommand.ts): PowerShell also reads the typographic quotes U+2018 to U+201B as a single quote, so double each of them like the ASCII one.
- `classifyAuthAllow` (frontend/src/lib/tunnelCommand.ts): This mirrors what `portal expose --auth-allow` and `--auth-email-list` accept for each method. The Go owners are `normalizeApplicationAuthSubject` and `normalizeAllowed` (`sdk/appauth/credential.go`), `normalizeProviderPrincipal` (`sdk/appauth/appauth.go`), and `identity.NormalizeEVMAddress`. Email takes the email and `@domain` entries of oidc and saml, but no `sub:<id>`, because a mailbox has no other id. The browser has no Keccak, so a mixed-case wallet address is not checked against its EIP-55 checksum here; the tunnel rejects a bad one at start.
- `CANONICAL_SHAPE_PATTERN` (frontend/src/lib/exposeName.ts): The relay rejects names shaped like a canonical label: a 40-character hex address, alone or after a hyphen (`utils.NormalizeServiceName`).

- `AUTH_CALLBACK_PATH`, `AUTH_SAML_ACS_PATH`, `AUTH_SAML_METADATA_PATH` (frontend/src/lib/apiPaths.ts): Application callback paths mirror the `PathApplicationAuth*` constants in `types/paths.go`.
